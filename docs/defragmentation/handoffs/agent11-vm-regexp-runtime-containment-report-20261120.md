## Scope of what was changed

All files live only under `tests/defragmentation/security/agent11_*`, `.github/workflows/agent11-*` and documentation. The original `apps/desktop-ui/package-lock.json` Git blob `eebc9228dd404f0b9f9bd55f2665ab3e00fe9dfa` continues to lock official `picomatch@4.0.7` (dev:true); no alternate npm package, tarball, `npm overrides`, first-party guard or desktop application code changed.

The experimental source `agent11_vm_regex_wrapper_candidate.cjs` uses a subclass of native `RegExp` and a synchronous Node `vm.Script.runInContext` deadline around `RegExp.prototype.exec.call(regex,input)`. It temporarily replaces the original picomatch's *internal* and public `toRegex` factory, leaving its matcher/parser/compiled regex **source and flags** unchanged. It reconstructs the native main-realm `RegExp.exec` result (including captures, input, index and supported groups) on successful matches, and on deadline throws `ERR_AGENT11_PICOMATCH_DEADLINE` instead of silently lying that the source is not matched. A test-only `NODE_OPTIONS=--require=<absolute path to agent11_vm_regex_wrapper_preload.cjs>` loads the experimental hook before a Node Vite/Vitest subprocess; per-process `calls/timeouts/errors` logs establish only **local** hook activity.

**Not production approved:** `vm` is *not* assumed to be a full sandbox; the deadline only covers this one synchronous RegExp execution path, NOT compiler/parser computation and NOT all other module APIs or process CPU/memory limits. The implementation must not be silently included in any app package.

## Known security and compatibility limitations

1. **Compilation is not bounded.** Original picomatch `parse`, `scan`, `makeRe`, `compileRe`, `toRegex` can do significant synchronous work before any `RegExp.exec` hook; a pathological large/complex glob may exhaust resources there.
2. **Direct public API bypasses.** Callers can invoke `RegExp.prototype.exec.call(guardedRegex,input)` or hand an unguarded native RegExp into `picomatch.test` and avoid the subclass override. Other RegExp symbol methods, `g/y/d` flags, exotic custom `format`, `onMatch` callbacks and direct parser API paths lack full source-exact proof.
3. **Execution time only, not a total budget.** A per-`exec` deadline of 80ms does not bound aggregate many-call resource consumption or heap allocations. Cross-realm identity, capture array property descriptors and RegExp subclass species behavior need broader platform testing.
4. **Fail-closed means non-transparent behavior.** Legitimate but unusually slow patterns might throw instead of matching; silent `false` fallback is disallowed because it could omit sources without failing the build. Original strict boolean safety probes are RED and must never be reclassified as PASSED.
5. **Experimental harness and process topology.** A preload's ability to patch one original CJS module in a given process does not show that every Vite/Vitest bundled copy/import path is protected; opt-out and altered process environment remain potential bypasses. Hardcoded repo working paths and Node 22 support are not a supported generic npm package distribution.
6. **Supply chain/independent authority.** No maintained, independently reviewed package source/tarball, pinned installation mechanism, Windows installed-app certification at final integration SHA, or independent Agent10 security approval exists. The historical browser/installer absence of named picomatch paths is separate mitigation evidence, not a repair.
