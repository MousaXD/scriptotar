## Actual residual exploitability and build scope

An attacker-controlled **glob pattern and near-miss input** can cause catastrophic RegExp backtracking when picomatch compiles/evaluates repeated, overlapping extglobs. Original official 4.0.7 baseline [#44596156345](https://github.com/MousaXD/scriptotar/actions/runs/44596156345) produced **17/19 Linux and 18/19 Windows child timeouts**. This is a confirmed pathological behavior, notwithstanding the **2026-11-18 withdrawal** of advisory GHSA-fc5q-39xc-vjpf and consequently clean audit reports. Do **not** equate an advisory withdrawal with changed program bytes.

On the exact current desktop lock, all four incoming references are development-only: `vite@7.3.7` (`^4.0.3`), `vitest@5.1.0` (`^4.0.7`), `tinyglobby@0.2.17` (`^4.0.4`), and `fdir@6.5.0` (optional peer `^3 || ^4`). No direct runtime npm dependency exists. Prior source-exact Linux/Windows browser-graph run [#44775812658](https://github.com/MousaXD/scriptotar/actions/runs/44775812658) found no picomatch module in compiled browser JS; historical .deb and installed NSIS inventories at **older owner integration SHA `50ed95608fc742db4a7cf1bdd2ac04fa8c5457e6`** found no named parser files [#44784540456](https://github.com/MousaXD/scriptotar/actions/runs/44784540456). **Those are exposure-scope facts, not a general safe-parser proof, and old installed-app artifacts do not certify current integration.**

An original hostile `import.meta.glob` path has actually caused Vite's build-side `tinyglobby → fdir → picomatch.test` route to hang, with a killable process deadline [#44805280533](https://github.com/MousaXD/scriptotar/actions/runs/44805280533). The trusted first-party source guard narrows supported build input, but cannot cover all third-party/plugin-produced patterns or mutable CI dependencies and is NOT the parser fix.

## Viable upstream engineering path / exact acceptance requirements

- Implement an **actual** safe matcher/compiler for overlapping repeated extglobs, including nested extglobs, repeated character classes/ranges, case folding, negative extglobs, brace/wrapper and post-group quantifier cases. It must preserve the original **correct result** and supported captures; it must not silently literalize valid patterns, treat timeout as `false`, or rely on JS prototype interception. A semantics-preserving automaton/IR with explicit bounded ambiguous-repeat evaluation, or an independently proved equivalent linear-time construction, is worth investigating; neither exists as a validated patch today.
- Preserve documented `picomatch()`, `isMatch`, `test`, `makeRe`, `parse`, `scan`, captures and all options used by Vite, Vitest, Svelte, tinyglobby, fdir. A `makeRe` or native RegExp escape route requires a specifically proven safety model, not simply a protected callable wrapper. Bound parser work, intermediate representation sizes, expansions and evaluation for adversarial inputs.
- Test the original **immutable 19** (1.2s killable child each), original **expanded 12** (1.5s child each), original **10** positive/negative matcher controls, all supported upstream fixtures, 180×84 match/capture comparison, independent fuzz/negative controls (including direct prototype/precompiled-regex bypasses), and adversarial long near-misses. Require full supported semantics, no timeout, no mismatched result on **Linux and Windows**. Tests should fail safely and retain exact original inputs and Git blobs.
- Verify an authenticated published upstream version **or** an independently audited, provenance-pinned minimal parser patch, reproducible tarball hash, license, lockfile determinism and uncompromised guard. Do not blindly `npm audit fix --force`, downgrade Vitest/Vite, suppress audit, or import a fork.
- On the **actual patched** source, run `npm ci`, npm audit (while interpreting advisory status separately), frontend `check/test/build`, real Vite `import.meta.glob` and source imports, all Svelte/Vitest/tinyglobby/fdir compatibility, Linux/Windows original installer and installed-app certification, and source-exact affected packaging/security gates. Independent Agent 10 must approve the *exact patch SHA and provenance* before Agent 00 considers integration; Agent 00 alone decides merge and release.
