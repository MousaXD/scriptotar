## What was implemented

- `crates/scriptotar-research/src/study_intelligence.rs`: deterministic, no-network `analyze_study_sources(project_id, study_id, analyzed_at, selected_material)`. Uses the existing observational `MetricSnapshot` and creator/age-matched peer comparison logic and the existing typed transcript feature/creative-beat vocabulary. Returns `StudyResearchReport` with **separate** `ObservedMetrics` and `StudyPatternObservation`.
- Source IDs are **canonical `study_sources.id`**. Original research/transcript UUIDs, project/Study UUIDs, locator, attachment `collected_at`, research `observed_at`, revision, access status, exact segment IDs and real timecode ranges are separate fields.
- The extractor quotes only opening/middle/closing literal text with bounded excerpts. CTA-like terms, spoken transition cues, questions and measured per-segment word/time spans are labeled **transcript-only interpretations**, never verified causal or creative claims. Missing segments, missing stats, missing peer groups, zero views, partial/untimed material and deleted sources are explicit limitations. No visual, retention or virality claims.
- `apps/desktop/src-tauri/src/services/study_research.rs`: a scoped SQLite reader that accepts only already attached real research/transcript IDs, caps source count at eight, caps text and segment JSON reads at 128 KB each, verifies project/source/study/active state, and never calls yt-dlp, remote providers or arbitrary files.
- An approval-only `AnalyzeEvidence` policy gate and `ToolExecutor` adapter use the **existing v8 effects ledger**, reserve before work, serialize a bounded, immutable local JSON report, and record a receipt only after durable write. `probe` can recover a persisted local report after an interrupted receipt, but never re-executes a missing/ambiguous effect. Retrieval rechecks active Study, revision, original source IDs and source availability. A previously available source that was subsequently revoked/deleted cannot be read from the report API.
- No new schema, credentials, platform scraping, frame analysis or provider egress.

### Artifacts, privacy and revocation

- JSON report files live beside `scriptotar.sqlite3` under `study-research-reports/<deterministic-artifact-uuid>.json`; contents contain bounded untrusted transcript excerpts, source locators, observed counters, project/Study IDs and effect identity, so they must be treated as **private user content**, not shareable cache. On Unix the directory is mode `0700`, new report files mode `0600`; Windows relies on the private application-profile directory ACL and needs installed-app verification. Writes use a private `create_new` temporary file, flush and sync it, atomically publish with a same-directory no-overwrite hard link, unlink the temporary entry, and (Unix) sync the parent directory before marking the effect Applied. Concurrent same-byte publications only succeed after a durability sync; different-byte publications fail closed without replacing the winner. Systems without compatible hard-link support fail closed rather than overwrite.
- The current implementation invalidates read access after source revision changes, deletion, detach, Study archive or project switch, but **does not physically erase old JSON**. Agent 00 must define per-profile retention and deletion, include or deliberately exclude report files in encrypted profile backups/migrations, and delete report and orphan `.pending` files when the user requests discard or profile deletion. Validate project/Study envelope identity before any targeted deletion; never accept a free-form filesystem path from IPC. A missing file with an Applied receipt is unavailable/uncertain and must **not** trigger fresh analysis or a paid call. Secure wiping of SSD storage cannot be guaranteed; rely on OS/profile encryption for physical media threats.
- Exact `scanned_at` and `updated_at` fields are **revision signals**, not content digests. Agent 00 should ensure all edits bump them and consider authenticated source hashes when adding higher-assurance provenance. Report inspection does not grant original content rights or bypass social-platform restrictions.

### 2026-11-21 Agent 03 concurrent artifact write hardening (source candidate pending exact-SHA CI)

A real eight-round two-thread regression uses opposite bytes with the same UUID and checks exactly one winner, immutable winner contents, idempotent same-byte rewrite and no stranded `.pending` files. If atomic publication or durability cannot be proven, no Applied receipt is authorized; no retry of a possibly published charged effect is inferred. This local zero-cost research artifact write change does not implement cross-process source-mutation locking or paid-provider dispatch. New exact-head workflows and independent review remain required before integration.
